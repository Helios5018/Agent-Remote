# 公网暴露指南

先说结论：**"随便找个 Tunnel 把 4318 端口暴露出去" 不够。**

这个服务能远程往你的终端里打字、发 Ctrl+C。它一旦可达，攻击面就不是"泄露一点数据"，
而是"别人能操作你的 Mac"。所以公网这一层要单独设计，而不是顺手挂个隧道。

---

## 三档方案，按推荐顺序

### A. Tailscale / WireGuard（推荐）

严格说这不叫"公网暴露"：设备加入你自己的私有网络，别人在公网上**根本扫不到**这个服务。

```bash
# Mac 上
brew install tailscale && sudo tailscale up

# 服务照常只监听本机即可，Tailscale 会给一个 100.x 的地址
bun run start
# 手机装 Tailscale 登录同一账号，访问 http://<mac-tailscale-ip>:4318
```

- 认证在网络层（Tailscale 账号 + 设备授权），PIN 变成第二道锁。
- 4 位 PIN 在这个方案下完全够用。
- 想更方便可以开 `tailscale serve` 拿 HTTPS 域名。

### B. Cloudflare Tunnel + Cloudflare Access（公网可达，但前面有门）

需要"任意设备打开网页就能用"时选这个。

```bash
brew install cloudflared
cloudflared tunnel login
cloudflared tunnel create agent-remote
# 把 tunnel 指向本机回环，服务不用对外监听
cloudflared tunnel route dns agent-remote agent.example.com
cloudflared tunnel run --url http://127.0.0.1:4318 agent-remote
```

然后在 Cloudflare Zero Trust 里给这个域名加一条 **Access 策略**（只允许你的邮箱 / Google 账号 / OTP）。

```bash
# 服务端要知道自己在代理后面
bun run start -- --trust-proxy
```

- 真正的鉴权是 Cloudflare Access，PIN 是第二道。
- 有免费额度，HTTPS 自动搞定。

### C. 裸 Tunnel + PIN（最弱，只适合临时用）

```bash
cloudflared tunnel --url http://127.0.0.1:4318      # 随机 trycloudflare.com 域名
# 或 ngrok http 4318
bun run start -- --trust-proxy
```

此时**唯一**的门就是 PIN。这种情况下：

- 至少用 6 位：`bun run start -- --pin-length 6 --rotate-pin --trust-proxy`
- 用完就关隧道，别长期挂着
- 隔一阵 `--rotate-pin` 换一次

## 4 位 PIN 到底安不安全

4 位只有 1 万种组合，**没有限流的话几秒钟就被爆破**。能用的前提是服务端的指数级锁定
（`apps/server/src/security/throttle.ts`）：

| 规则 | 值 |
|---|---|
| 免费尝试次数 | 5 次 |
| 第 5 次失败后锁定 | 60s，之后每失败一次翻倍 |
| 锁定上限 | 1 小时 |
| 失败计数清零 | 需要连续 6 小时没有新失败 |
| 全局闸门（防换 IP） | 所有来源合计 20 次失败 → 全局锁 15 分钟 |

算下来攻击者**每天最多试 ~24 次**，穷举 1 万种组合要一年以上，期望命中约半年。
外加：

- 每次触发锁定，服务端终端都会打印 `[security]` 告警，你会看见。
- `--unlock` 可以立刻解锁（比如你自己手抖输错了）。
- `/api/audit` 记录每一次失败尝试的来源。

**判断标准**：走方案 A/B（前面还有一层认证）→ 4 位够用；
走方案 C 且长期挂着 → 请用 6 位以上（100 倍难度，`10^6 / 24 ≈ 114 年`）。

## 公网暴露前的检查清单

- [ ] **让 Tunnel 连 `127.0.0.1:4318`，服务本身不要 `--lan`**（少一个暴露面）
- [ ] 开 `--trust-proxy`：否则限流会把所有请求算成同一个来源，且 Cookie 不会带 `Secure`
- [ ] 确认入口是 HTTPS（三种 Tunnel 都自带）
- [ ] 方案 C 请 `--pin-length 6 --rotate-pin`
- [ ] 确认 `~/.cmux-agent-remote/hook.json` 权限是 `600`（服务自动设置）
- [ ] 心里有数：登录后即可读写 Agent（PIN 就是控制权）

---

## 已经内置的防护

| 威胁 | 现有防护 |
|---|---|
| PIN 爆破 | 指数级锁定 + 全局闸门 + 告警 + 审计（见上） |
| 伪造 `X-Forwarded-For` 绕限流 | 默认不信任，只有显式 `--trust-proxy` 才读 |
| 用 PIN 伪造 Hook 事件 | Hook 用独立的长随机密钥，且**只接受本机回环**请求，带 XFF 的一律拒绝 |
| Cookie 被中间人截获 | HTTPS 入口 + `HttpOnly` + `SameSite=Lax` + 检测到 https 时自动加 `Secure` |
| CSRF | `SameSite=Lax` + 所有写操作是 JSON POST |
| 误操作别人的 Agent | 写操作必须在 URL 里显式指定 surface |
| 命令注入 | 所有 cmux 调用走参数数组 + `--`，不经过 shell |
| 目录穿越 | 静态文件服务对 `..` 返回 403 |
| 泄露对话内容 | SQLite 不存终端输出与 prompt，审计只记长度 |

## 还没做的（想更硬就得加）

- **没有 2FA / TOTP**：真正长期公网建议靠 Cloudflare Access 这类外层补上。
- **没有设备绑定**：Session Cookie 不绑设备指纹，Cookie 被复制就能用。
- **没有 IP 白名单**：可以在 Tunnel / 反代层加。
- **没有自动告警推送**：锁定只打印在服务端终端，不会推到手机。
- **单用户**：一个 PIN 一套权限，没有多用户与分级权限。

## 出问题了怎么办

```bash
# 立刻换 PIN，并踢掉所有已登录设备
bun run start -- --rotate-pin

# 自己输错被锁了
bun run start -- --unlock

# 换 Hook 密钥（换完各 Agent 会话要重开才会带新密钥）
bun run start -- --rotate-hook-token

# 看看谁在尝试
curl -s -b cookie http://127.0.0.1:4318/api/audit | jq '.entries[] | select(.action|startswith("auth"))'

# 最快的止血：关掉隧道进程
```
