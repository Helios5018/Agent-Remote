# 会话输入可靠性优化

**核心思路**：按 surfaceId 保存当前页面内存草稿与发送状态；明确区分发送完成、请求被拒绝、文本已写入但提交结果未知、发送结果未知。结果未知时禁止直接重复发送，核对终端后继续。新 tab 创建成功后即使启动失败也返回已有 tab，避免重复创建。

**改动范围**：packages/protocol API；server 的 surfaces 路由；web 的输入状态、Composer、SessionPage、AppStore、NewSurfaceRow；API 和前端行为测试、使用/API 文档。

**影响评估**：草稿只在当前页面内存保留，刷新后清除；主动登出和明确关闭会话清除。认证过期保留内存草稿供重新登录恢复。不会将 prompt 写入 SQLite、localStorage 或 sessionStorage。命令返回成功仅表示 cmux 接收，不表示 Agent 完成处理；异常不等于未执行。新接口保留原有成功响应字段并追加可选启动失败信息。

## 执行与验证

1. 建立按会话隔离的草稿与请求状态，处理切换期间请求返回、重复点击和登出后的迟到响应。
2. 服务端报告输入失败阶段；客户端对网络中断、无效响应保守显示结果未知。
3. 创建后启动异常返回 surfaceId 和阶段提示，前端进入已有会话查看并手动恢复。
4. 补充故障注入 API 测试、草稿生命周期测试与浏览器交互验证；运行类型检查、测试和构建。
5. 同步使用/API 文档并记录验收结果。

## 完成记录（2026-09-05）

以上步骤已完成。草稿通过独立的 DraftStore 按 surfaceId 订阅，输入与按键共用发送中标记，阻止同页面内重复点击。关闭/登出后迟到的响应不会恢复旧草稿；认证过期保留当前页面内存状态。仅补 Enter 再次失败时，仍保留“正文已写入”的事实。

服务端新增两个输入异常 code；新建 tab 的启动失败通过可选 launchError 返回，前端打开已有 tab 显示恢复提示。创建请求整体结果未知时，先检查结构树再允许再次创建。成功响应正文也经过 schema 校验，避免代理返回 HTML 却被当成发送成功。
